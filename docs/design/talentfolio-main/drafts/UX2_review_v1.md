# UX2 리뷰 v1 — 모션 안무 · 접근성 · 성능 (라운드3 D/E/F)

> 검토자: UX 디자이너 2. 근거: 각 시안 `index.html`의 `<script type="module">`·CSS를 직접 읽음, `QA_round3_v1.md`, `ROUND3_BRIEF.md`, B_ui(모션 참고용).
> 코드는 수정하지 않았다.

## 공통: anime.js 4.0.2 API 점검
- 세 시안 모두 `https://cdn.jsdelivr.net/npm/animejs@4.0.2/+esm`에서 `animate / createTimeline / stagger / utils / onScroll`만 import한다. 모두 4.0.x에 있는 API다.
- `splitText`는 **4.1.0에서 추가**되어 4.0.2에는 없다. 세 시안 모두 split을 직접 구현했으므로 올바르게 처리했다. 공식 문서 페이지는 WebFetch로 일부만 확인됐고, 버전은 changelog 기준으로 판단했다.
- 쓰인 ease 문자열(`outExpo`, `outBack(2)`, `outElastic(1,.6)`, `inOutQuart`, `outBounce`, `linear`)은 모두 v4 형식에 맞다.
- `onScroll`의 `enter:'bottom top'`, `sync:true`, `onEnterForward` 사용(D·F)도 v4 형식에 맞다.
- **E는 `onScroll`을 한 번도 쓰지 않는다.** 브리프의 "스크롤 연동은 onScroll 우선"을 어겼고, 자체 rAF 엔진을 쓴다(성능 항목 참고).
- **포커스 스타일**: `:focus-visible` 정의는 F에만 있다. D·E는 키보드 포커스가 브라우저 기본값에 의존한다.

### (2) 꼭 고칠 것
- **P0 히어로 가독성**(QA 치명): `#crowd`(z-index 3, 높이 62vh)가 서브카피와 CTA를 덮는다. 다음 중 하나로 고친다.
  - `#crowd` z-index를 `#heroCopy` 아래로 내리고 높이를 40vh 안팎으로 줄인다.
  - 또는 `.hero-copy` 하단 요소에 흰 배경 pill을 깔아 대비를 확보한다.
  - 군중이 보이는 장소는 "출발" 마스크 단어 안으로 충분하다.
- **P1 canvas 비용**: `drawMask`가 매 프레임 `filter:'invert(1) brightness(1.6)'`를 켠 채로 crowd canvas 전체를 다시 그린다. canvas filter는 비싸다.
  - 스프라이트를 미리 반전한 offscreen 이미지를 한 번만 만들어 쓴다.
  - 히어로가 화면 밖이면 IntersectionObserver로 루프를 멈춘다.
  - `#crowd2`(CTA 영역)도 화면에 없을 때 계속 그린다. 같은 방식으로 정지한다.
- **P1 스크롤 핸들러**: `addEventListener('scroll', () => requestAnimationFrame(tick))`에 중복 방지 플래그가 없어 프레임당 rAF가 여러 번 쌓일 수 있다. `ticking` 플래그를 둔다.
- **P1 mqLoop**: 매 프레임 `scrollWidth`를 읽는다(레이아웃 읽기). 너비는 resize 때만 캐시한다. RM에서도 rAF가 계속 돈다.
- **P1 모바일 핀**: 860px 이하에서도 히어로 200vh 핀과 데모 300vh 핀이 유지된다. 375px에서는 데모 핀을 해제해(E처럼 `position:relative`) 4단계를 세로로 정적으로 보여준다. 포인터 패럴랙스는 `(hover:hover)`일 때만 연결한다.
- **P2 키보드**: `:focus-visible` 스타일을 추가한다. split 글자는 스크린리더가 글자 단위로 읽으므로 부모에 `aria-label`, 각 `.ch`에 `aria-hidden`을 준다(F 방식).

### (2) 꼭 고칠 것
- **P0 스크롤 성능**: `tick()`이 스크롤하지 않아도 매 프레임 `frame()`을 돈다.
  - 그 안에서 모든 `[data-m]` 요소의 `getBoundingClientRect`를 읽고 곧바로 스타일을 쓴다. 이 읽기→쓰기 교대 때문에 매 프레임 레이아웃 스래싱이 생긴다.
  - `filter: blur()`가 스크럽돼 리페인트 비용이 크다.
  - 수정 방향:
    - 요소별로 `onScroll({ target, enter, leave, sync:true })` + `animate`로 옮긴다. 브리프 요구 사항이기도 하다.
    - 자체 엔진을 유지한다면 읽기를 한 번에 모은 뒤 쓰기를 한 번에 하고, scroll 이벤트가 있을 때만 갱신하고, 화면 밖 요소는 IntersectionObserver로 건너뛴다.
- **P0 데모 제목이 흩어진 채 보임**(QA): `splitFrame`의 등장 구간이 `p/0.3`이라서 제목이 화면 하단 30% 구간에 있는 동안 글자가 ±60px로 흩어져 있다.
  - 등장 구간을 `p 0~0.15`로 줄이거나, 제목이 뷰포트 하단에서 25% 올라왔을 때 one-shot으로 재생한다.
  - 역할 카드 뒤 빈 공간은 데모 섹션 높이와 sticky 시작점을 점검한다.
- **P1 히어로 레이어**: 군중이 성장곡선·스티커와 겹쳐 잘 보이지 않는다(QA). 스티커를 군중 띠 위쪽으로 올리고 `.hero-score`를 군중 띠 밖에 둔다.
- **P1 CTA 버튼이 유일한 fade-up**이다. 덩굴 끝에서 버튼이 "자라나는" scaleY(transform-origin bottom)로 바꾼다.
- **P1 모바일**: `demoFrame`이 820px 이하에서도 매 프레임 스타일을 다시 쓴다. `mobDone` 이후에는 return만 한다. 모바일에서 `[data-m]`의 `60vw` 슬라이드는 가로 오버플로를 확인해야 하며, 부모에 `overflow-x:clip`을 준다.
- **P2 접근성**:
  - 드래그 스티커는 포인터 전용이다. 장식이므로 `aria-hidden`을 준다.
  - split 글자에 `aria-hidden`이 없고, `:focus-visible`이 없다.
  - RM일 때 `frame`이 스크롤마다 실행되지만 바로 return하므로 문제없다.

### (3) 빌려올 것
- D의 IntersectionObserver one-shot 퇴장(`watch` enter/leave) → 일부 요소를 스크럽이 아닌 순간 재생으로 바꿔 리듬을 만든다.
- F의 `#okBtn` 클릭 승인 인터랙션 → E 데모의 도장을 사용자가 직접 찍게 한다.
- D의 오도미터: 이미 같은 방식이 있다. D의 "출발" 마스크 단어 기법을 "쑥쑥"에 적용하면 히어로 레이어가 한 겹 늘어난다.

### (2) 꼭 고칠 것
- **P0 색과 빈 화면**(QA):
  - 군중이 회색으로 전체를 덮어 푸른/초록 색감이 거의 보이지 않는다. `#crowd` opacity `.3+spot*.5`가 회색 막을 만든다. dim 구간 외에는 군중을 화면 하단 40vh로 제한한다.
  - 핀 스크럽 중 화면 상단 절반이 비는 구간(p≈.32~.45)이 있다. 타이틀 퇴장과 JD 카드 등장을 겹치거나 그 구간에 phase 문구를 크게 둔다.
- **P0 모바일 핀**: 760px 이하에서도 `#hero` 420vh 핀과 `#loop` 320vh 가로 트랙이 그대로다. 375px에서는 4뷰포트 넘게 같은 화면을 스크롤하게 되고, fixed 카드와 스포트라이트 라벨이 겹친다.
  - 모바일에서는 히어로를 160~200vh로 줄인다.
  - 루프는 RM 분기처럼 `position:relative` + 세로 나열로 바꾼다. CSS가 이미 있으므로 미디어쿼리에 재사용하면 된다.
- **P1 성능**:
  - `heroUpdate`가 스타일을 쓴 직후 `jd.getBoundingClientRect()`를 읽는다(강제 레이아웃). 매 스크롤 프레임마다 생긴다. JD 카드 좌표는 transform 값으로 계산하거나 쓰기 전에 읽는다.
  - 군중 이동이 `o.speed*16`(프레임당 고정)이라 120Hz 모니터에서 2배 빨라진다. dt 기반으로 바꾼다.
  - fixed canvas가 페이지 전체에서 매 프레임 28명을 그린다. 히어로를 지나면 opacity만 낮추지 말고 그리기 빈도를 낮추거나 정지한다.
- **P1 접근성**:
  - `split()`이 모든 `.ch`에 `aria-hidden`을 준다. `demoH`와 `loopH`에는 `aria-label`이 있지만, `krTitle`(히어로 h1)과 `finalH`에 `aria-label`을 주는 코드가 스크립트에 보이지 않는다. 마크업에 aria-label이 없다면 h1이 빈 제목이 되므로 확인 후 추가한다.
  - 루프 제목 스크램블은 `setInterval`로 `textContent`를 바꾸므로 라이브 영역이 아니면 괜찮다.
- **P2 퇴장 보강**: works 제목은 반대 방향 skew로 퇴장시키고, 숫자 박스는 fade-down 대신 테두리 드로잉이나 오도미터로 바꾼다. 마지막 제목은 회전 범위를 ±20°로 줄이고 outBounce를 outBack으로 바꾼다.

### (3) 빌려올 것
- D의 "출발" 마스크 단어(글자 안에 군중) → F의 "지평선 너머"에 적용해 색을 넣는다(하늘→초록 그라데이션 fill).
- E의 `M` 타입 사전(요소별 enter/exit 쌍) → 히어로 이후 섹션들의 퇴장 공백을 채운다.
- D의 statement 단어 채움 스크럽 → final 제목의 과한 bounce를 대체한다.

## 순위

1. **D 맑은 아침 하늘**
   - 요소별 등장과 퇴장이 가장 고르게 설계됐다. 마스크 단어, 포인터 깊이, 핀 흩어짐, 원형 clip이 함께 들어간 히어로가 브리프의 "기술 총집합"에 맞는다.
   - anime.js는 timeline과 onScroll sync를 정석대로 쓴다. RM 분기도 가장 꼼꼼하다.
   - P0는 레이어 순서 하나뿐이라 고치기 쉽다.
2. **F 지평선 너머**
   - 히어로 내러티브(군중 속 한 사람을 찾아 매칭하고 승인)가 제품 루프를 가장 잘 보여준다. onScroll one-shot과 RM 언핀 처리도 좋다.
   - 그러나 색 요구를 놓쳤고, 모바일 핀을 처리하지 않았으며, 후반 섹션에 퇴장 모션이 부족하다.
3. **E 새싹이 자라는**
   - 첫 화면 임팩트와 모션 어휘 다양성은 최고다.
   - 그러나 매 프레임 레이아웃 스래싱하는 자체 엔진이 실서비스에 그대로 옮기기 어렵다. onScroll을 쓰지 않아 브리프도 어겼고, 데모 제목 버그가 있다.
   - 엔진을 onScroll로 옮기면 D와 겨룰 수 있다.
