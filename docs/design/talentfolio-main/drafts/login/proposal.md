# talentfolio 로그인 시안 (LG1–LG3) — 2026-10-26

정적 시안이며 실제 인증과 연결하지 않았다. 공통 자원은 `_base.css`(토큰·H2 바·워드마크·폼 요소)와 `_form.js`(역할 토글·검증 데모)에 있다.
메인(`sky-landing.css`)의 토큰(cobalt/cerulean/ink/mist/sun/line)과 폰트(Pretendard 본문, Wanted Sans 제목, MaruBuri 강조), H2 미니멀 바, 워드마크 `talent<b>folio</b>`(Lora italic + swash)를 그대로 옮겼다. 로고 이미지는 쓰지 않는다.

## 기존 기능 확인 (talentfolio/src/components/AuthModal.tsx, 읽기만 함)
- 로그인: 이메일과 비밀번호. 회원가입: 이름, 역할(developer/designer), 직함. 오류 문구는 3종(잘못된 로그인, 이미 가입됨, 6자 미만).
- **소셜 로그인과 기업 역할은 현재 없다.** 그래서 시안에는 Google·카카오·회사 SSO 버튼을 `미연결` 태그와 함께 넣었다. 구직자/기업 구분도 시안에서 새로 제안하는 것이다. 실제로 반영하려면 계정 모델에 company role을 추가해야 한다.
- 오류 문구와 6자 규칙은 기존 것과 똑같이 맞췄다.

모션은 CSS만 쓴다(swash 드로잉, 해 떠오르기, 토글 thumb, 문구 교체 페이드, 단계 슬라이드). JS 애니메이션이 필요 없을 만큼 단순해서 anime-ui 규칙의 "CSS 한 줄이면 CSS" 원칙을 따랐다. 실제 구현에서 문구 교체 시퀀스를 다듬을 때는 anime.js v4 `createTimeline`으로 옮기면 된다. 모든 모션은 `prefers-reduced-motion`이면 꺼진다.

## 리뷰 루프 기록 (UI 디자이너 ↔ UX 디자이너)
Agent 도구로 별도 디자이너를 띄우지 않았다. 이 작업 자체가 서브에이전트로 실행 중이라서 한 에이전트가 두 역할을 번갈아 맡았다.

**R1 시안 → 상호 리뷰**
- UX → UI: (1) LG1 데모 카드에 `[hidden]`을 줬는데 `display:grid`가 덮어써서 구직자와 기업 목록 4줄이 동시에 보였다. (2) LG2 모바일 2단계에서 긴 이메일 칩 때문에 박스가 화면 밖으로 밀렸다. `overflow-x:clip`이 넘침을 가려서 scrollWidth 수치로는 드러나지 않았다. (3) LG3 문 제목이 버튼 안의 span이라 헤딩 탐색으로 찾을 수 없었다. (4) LG3 모바일에서 기업 문이 첫 화면 밖에 있다.
- UI → UX: (1) LG3 문구 "계정 하나로 둘 다 쓰지는 않습니다"가 정책을 확정한 것처럼 읽히고 차갑다. (2) 소셜 버튼은 현재 기능에 없으니 숨기지 말고 `미연결`로 표기해 기대치를 맞추자. (3) 수치는 TREND_BRIEF #5에 따라 `예시` 표기가 필요하다.

**R2 수정 → 재리뷰**
- 수정 내역: 전역 `[hidden]{display:none!important}` 추가. LG2는 `.stage` 그리드 열을 `minmax(0,1fr)`로, `.box`를 `min-width:0`으로 바꿔 칩 말줄임이 동작한다. LG3는 문 제목을 `<h2>`로 감싼 버튼(aria-expanded/controls)으로 바꿨다. 모바일 기업 바로가기 버튼을 추가했다(포커스 이동, reduced-motion이면 즉시 스크롤). 문구는 "로그인 뒤에도 메뉴에서 입장을 바꿀 수 있어요."로 바꿨다. 소셜·SSO 버튼에 `미연결`, 데모 수치에 `예시` 태그를 달았다.
- 재리뷰: 위 항목을 모두 브라우저에서 다시 확인했다. 남은 의견으로 UX는 LG2의 도메인 휴리스틱이 오판하면 혼란을 줄 수 있다고 봤고, 실제 구현에서는 서버 판단이 필요하다. UI는 LG1 모바일에서 데모 카드를 숨겨 히어로 차별점이 줄어든다고 지적했지만, 폼을 먼저 보여 주는 쪽을 우선하기로 합의했다.

## QA (http://localhost:8090/login/, 내장 브라우저)
- 1280px와 375px 모두 `scrollWidth == innerWidth`로 가로 넘침이 없다. 콘솔 오류는 0건이다.
- 빈 값으로 제출하면 오류 메시지가 뜨고 포커스가 첫 오류 필드로 간다. `aria-invalid`와 `aria-describedby`가 연결돼 있다. 서버 오류는 `role=alert` 데모로 보여 준다.
- LG1: 역할을 토글하면 문구가 기업용으로 바뀐다. LG2: 회사 메일을 넣고 계속을 누르면 2단계로 넘어가고, 비밀번호 필드로 포커스가 가며 SSO 안내가 뜬다. LG3: 기업 문을 열면 `c-email`로 포커스가 간다.
- label/for, 본문 건너뛰기 링크, focus-visible 링(기업 문에서는 sun 색), 비밀번호 보기 버튼(aria-pressed), reduced-motion을 적용했다.
- 한계: 미리보기 패널이 백그라운드일 때는 CSS 애니메이션 진행이 늦어 캡처가 반투명하게 찍히는 경우가 있었다. 계산된 스타일로 opacity 1을 확인했다. 실기기에서 다크 모드와 스크린리더 낭독은 검증하지 않았다.

## 추천 순위
1. **LG1 아침 창**: 메인의 하늘 그라디언트와 제품 데모 톤을 가장 자연스럽게 잇는다. 토글 하나로 두 입장을 모두 설명하고, 구현 비용도 가장 낮다.
2. **LG3 두 개의 문**: 구직자와 기업의 구분이 가장 명확하다. B2B(스카우트 건·HIL 승인) 진입점을 따로 보여 주기에 좋다. 다만 반전 면이 메인의 밝은 톤과 대비가 강하다.
3. **LG2 한 줄씩**: 가장 미니멀하고 SSO 확장성이 좋다. 하지만 2단계라 클릭이 하나 늘고, 도메인 휴리스틱에 서버 지원이 필요하다.
