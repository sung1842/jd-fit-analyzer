# 교차 리뷰 — UI 디자이너(B) 관점: A_planner, C_ux

기준: 시각 완성도 / 타이포·컬러·간격 일관성 / "AI가 만든 느낌" 잔존. (코드·문서 리딩 기반. 렌더 확인은 총괄 QA 결과 참고)

## A_planner (스토리·메시지)
**좋은 점**
- 서사 구조가 가장 탄탄함: Prologue 문제 제기 → Ch.01~04 → HIL 반전 → 지원자 → CTA. 각 섹션의 존재 이유가 분명함.
- copper 하나로 통일, 지원자 톤은 같은 색의 저채도(`#F6D9CF`). 브리프 #6 준수.
- 21st.dev 인용이 구체적임(Text Rotate landing-hero, Hyperiux Timeline).

**문제점**
- 디스플레이 크기가 6종으로 흩어짐(clamp 상한 200/140/96/88/80/52). 위계가 흐려지고 "다 크게"가 되어 오히려 임팩트가 줄어듦.
- radius가 4·8·12·14·16·999px로 제각각이고 회색도 비슷한 값이 7~8개(#eef0f3, #f2f3f6, #f1f3f6, #eceef2…). 토큰화가 안 되어 있어 "생성된 듯한" 미세 불일치가 남음.
- 질감·소재감이 없고 차가운 블루그레이(#F6F7F9)뿐이라 기본 SaaS 템플릿 인상이 남음.
- 요소 표의 상당수가 카테고리 링크 수준(Toggle/Steps/Number/Stat/Animated).

**가져올 것**
- Prologue의 "헤드헌터 한 명이 볼 수 있는 포트폴리오는 한정" 메시지. 단, B안 숫자 밴드와 겹치므로 밴드 카피로 흡수할지 v3에서 검토.
- 워크스루 대안 레퍼런스로 Hyperiux Timeline.

## C_ux (인터랙션·전환)
**좋은 점**
- 데모 상태 설계(idle→searching→candidates→scored→approved), 키보드·aria-live·URL `?role=` 반영이 세 시안 중 가장 완성도 높음.
- 숫자 키네틱(Number Flow)과 링 게이지 동기화는 시각적으로도 강한 장치.
- 토큰 수가 적고(`--ac`, `--ac-d`) 간격이 비교적 일관됨.

**문제점**
- 헤드라인이 서술형 한 문장이고 크기 위계가 3단으로 평이함. 키네틱 타이포(#4)의 존재감이 약함.
- 밝은 블루그레이 배경 + 흰 카드 + 20px 둥근 모서리 조합은 "AI 생성 SaaS" 인상에 가장 가까움. 질감이나 포인트 장치가 없음.
- 후보 카드 팬은 레퍼런스 미확정(Card 컬렉션) — 시각 디테일 근거가 약함.
- `--ac-d #B5523A`와 B안 `--accent-ink #B85A40`처럼, 진한 copper 값을 세 시안이 통일해야 함.

**가져올 것**
- "데모 건너뛰고 시작" 상시 링크(막힘 방지), 세그먼트 토글의 `role=radiogroup` + 화살표키.
- 승인 완료 토스트 문구 "제안 대기열에 추가됨(예시)" → B안 HIL 카드 결과 문구에 적용 후보.

## 세 시안 공통 제안
- 진한 copper 하나로 합의(`#B85A40` 제안. 밝은 바탕 대비가 약 4.3:1 추정으로 AA 본문 4.5 경계라, 본문용은 더 어둡게 조정 필요).
- 배경: 고정 조건은 `#F6F7F9`. B안의 웜 페이퍼 `#F6F4F0`은 근사치라 총괄이 판단 필요.
