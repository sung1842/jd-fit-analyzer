# 시안 C(UX) → A·B 리뷰 (UX 관점)

정적 코드 리딩 기준(브라우저 패널 미사용). 렌더 확인은 총괄 QA 결과에 의존.

## A (기획자, 스토리 중심)
**좋은 점**
- 첫 5초 메시지가 가장 명확: "AI가 찾고, 사람이 정하고, 작업물이 증명한다" 3박자. HIL 차별점이 카피에 녹아 있음.
- 역할 토글이 `role=tablist/tab/tabpanel` + `aria-controls` + 화살표키 → 접근성 구조가 세 시안 중 가장 정석.
- 워크스루 sticky 2열(좌 서사/우 시각물)이 네이티브 스크롤 유지. awwwards 근거(Radian·Neutomni SOTD)가 가장 탄탄.
**문제점**
- 역할별 경로가 스크롤 서사 끝(섹션 5)에서야 CTA로 합류 → 헤드헌터가 30초 안에 /desk 로 가기 어렵다. 히어로에 역할 CTA 필요.
- 지원자 이야기가 별도 섹션(4)으로 분리되어 토글 선택과 섹션 순서가 연동되지 않음(지원자 선택해도 헤드헌터 서사를 먼저 읽게 됨).
- 화살표키가 포커스만 옮기고 선택은 자동 전환(automatic activation)인지 확인 필요 — 전환 wipe 가 포커스 이동마다 발생하면 멀미 유발.
- 토글 21st.dev 인용이 카테고리 수준.
**가져올 것**: 3박자 카피 구조, 워크스루 큰 챕터 번호, tablist 의 `aria-controls` 연결.

## B (UI, 비주얼 중심)
**좋은 점**
- 시각 언어가 가장 풍부: 종이 바탕, 먹색 ink, accent-ink/soft 명도 단계, 카드 미세 회전·테이프. 그러면서 포인트 1색 규칙 준수.
- 히어로 데모에 인스펙터 콜아웃 → 초기 상태에서도 "무엇이 나오는지" 보임.
- 호버 스크램블을 포커스에도 발동, 한글 자모 치환 → 키보드 사용자 동등 경험.
**문제점**
- 토글이 `aria-pressed` 버튼 2개(group) → 상호배타 선택은 radiogroup/tablist 가 의미상 맞음. 화살표키 이동 없음.
- 데모 카드 진입 `rotate:(el,i)=>[0,rot[i]]` — v4 함수형 값이 배열(from/to)을 반환하는 형태는 문서상 보장되지 않음. `{from,to}` 객체로 바꾸는 편이 안전(내 시안도 같은 문제였고 수정함).
- 마퀴·틸트·스크램블·회전·카운트업이 첫 화면에 겹쳐 모바일에서 주의 분산. 860px 이하 한 단계 브레이크포인트뿐 → 375px 검증 필요.
- CTA 가 역할과 무관하게 1개 → 지원자 경로가 히어로에서 보이지 않음.
**가져올 것**: ink `#17140F`, accent-soft `#F2B8A6` 하이라이트, 카드 ±1° 회전·테이프 디테일, 인스펙터식 결과 미리보기 콜아웃.

## 공통으로 C 가 지켜야 할 차별점
역할 선택 → 데모 → 역할 CTA 가 한 화면 안에서 끝나는 것. 시각 장식은 B 에서 빌리되 첫 화면 동시 모션은 2개(회전 직무명, 사용자 조작 반응) 이하로 유지.
