**콘셉트 한 줄**: 오늘 심은 작업물이 덩굴처럼 자라 사람(헤드헌터)에게 닿는다. 하얀 바탕에 손그림 군중이 걷고, 그 위로 새싹 그래픽이 뻗어 오른다.

## 히어로 구성 (총집합체)

1. **레이어 구조(뒤→앞)**: 덩굴 SVG(선 드로잉) → 군중 canvas(Skiper39을 gsap 없이 vanilla로 옮김, 같은 스프라이트 15x7) → 거대 타이포 "커리어가 / 쑥쑥 자란다" → 드래그 스티커 3개, 핏 점수 카드.
2. **인트로**: 글자가 하나씩 아래에서 랜덤 회전·스케일로 튀어 오름(elastic) → 덩굴 두 줄이 그려짐 → 덩굴 위 5곳에 잎이 피어남 → 스티커가 팝 → 핏 점수가 0에서 92%까지 올라감(예시).
3. **인터랙션**: 글자에 호버하면 통통 튐 / 커서 근처를 걷는 사람은 걸음이 빨라지고 깡충 뜀(군중과 상호작용) / 마우스 패럴랙스(타이포와 덩굴이 반대로 움직임) / 스티커 드래그 후 놓으면 젤리처럼 튕김.
4. **퇴장(스크럽)**: 글자는 좌우 번갈아 흩어지며 위로 사라지고, 군중은 아래로 가라앉으며 커짐(깊이), 덩굴은 확대되며 흐려짐.

## 섹션별 등장/퇴장 모션 표

스크롤 진행도 p는 요소 상단이 화면 하단에 닿을 때 0, 요소 하단이 화면 상단을 지날 때 1이다. 등장은 p 0~0.3, 퇴장은 p 0.75~1 구간에서 스크럽된다(되감기 가능).

## 기술 메모
- anime.js v4.0.2 ESM에서 `animate`, `stagger`, `utils`만 import한다(시안 B와 같은 셋으로 4.0.2 가용성 확인). `onScroll`/`splitText`는 4.0.2 문서에서 직접 확인하지 못했으므로 쓰지 않았다. 스크롤 스크럽은 rAF와 요소별 진행도 함수로 직접 구현했다(`M` 맵: 타입마다 enter/exit 함수). 총괄이 4.0.2에 `onScroll`이 있다고 확인하면 `M` 맵을 `onScroll({sync:true})`로 옮길 수 있다.
- 군중: Skiper39 로직(방향 랜덤, offsetY power2.in, timeScale 0.5–1.5, 위아래 bob)을 그대로 옮겼다. 스프라이트를 못 불러오면 canvas를 숨긴다(콘솔 에러 없음, 이미지 404 네트워크 로그만 남음).
- 역할 진입 링크: `/start`, `/studio`, `/desk`.

### v2.1 (총괄 실렌더 QA)
- 데모 제목 원인: 제목이 sticky 핀 안에 있어 핀 동안 rect가 화면 상단에 고정된다. 그래서 진행도 p가 퇴장 구간(>0.85)에 머물렀고, 글자마다 상승량(1+i%3)이 달라 줄과 순서가 섞여 보였다. 레이아웃 문제가 아니라 transform 문제였다.
- 수정: split 제목을 스크롤 스크럽에서 빼고, 뷰포트에 20% 들어오면 1회 재생(IO + anime stagger)하게 했다. 완료되면 transform을 none, opacity를 1로 고정해 정상 문장으로 남는다.
