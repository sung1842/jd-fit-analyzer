# Review B: A(시각)·C(구조) 교차 검토 (모션·레이아웃 관점)

검토자: 기획자 B · 2026-10-25 · 추가 fetch는 하지 않았다. 판단 근거는 B 1라운드 때 확인한 자료다.

## 1. 동의하고, 겹쳐서 근거가 강해지는 트렌드
- **제품 = 히어로 (만져보는 데모와 인스펙터 목업)**: C-T1(Heron·YumLog·Butter)과 B-T6(인스펙터 패널), A-T6(작업물 = 비주얼)가 같은 결론이다. 세 관점이 모두 일치하는 가장 강한 합의점이다. 근거는 독립 사례 6개 이상이다.
- **역할 토글을 히어로로 끌어올리기**: C-T5(Dwell)와 B-T2(드래그 토글 + 팔레트 전환)가 일치하고, A-T1(같은 포인트 색의 명도 차이로 역할 구분)이 시각 규칙을 보완한다.
- **스크롤 시나리오 워크스루 (업로드 → 분석 → 승인 → 제안)**: C-T3·C-T2(HIL 명시)와 B-T1(스크러빙과 % 카운터, metic)이 같은 섹션을 가리킨다. C의 "승인 단계 하이라이트"는 모션으로 강조하기에 적합하다.
- **키네틱 한글 타이포 (직무명 회전·스크램블)**: A-T2와 B-T3가 같은 근거(Signal-A·FORMAT)와 같은 예시를 들었다. A의 "고정폭 처리"와 B의 "aria-label 유지"를 함께 채택한다.
- **실재감 있는 숫자와 카운트업**: C-T4(Arg·Heron 수치)와 B-T7(metic·Grande Charte 카운터)이 겹친다.
- **포트폴리오 실물 마퀴**: A-T6과 C-섹션2가 일치한다. B는 마퀴 남용을 경고했지만, 로고가 아니라 실제 작업물이면 의미가 있으므로 동의한다(호버 시 정지 필수).
- **피해야 할 패턴**: 세 문서 모두 같은 목록을 냈다(보라·파랑 블롭, 글래스, 3열 아이콘 카드, 균일한 fade-up). 확정해도 된다.

## 2. 근거가 약하거나 [추정]에 기댄 주장
- A-T3 물성·질감: 핵심 근거 Olivir는 웹사이트가 아니라 브랜딩 작업이다. Painted Dog는 [추정]이고, Half the Sky의 석고 질감은 텍스트로만 확인했다. 웹 랜딩 트렌드로서 확산도 "중"은 과대평가로 보며 "약~중"이 맞다고 본다.
- A-T7 흑백↔컬러 토글: [확인] 근거는 Arc Marumo 하나뿐이고, FORMAT·OFFFForum은 추정이다. 약하다.
- A-T5 오가닉 3D와 B-T4 리퀴드 모핑: 둘 다 근거가 recent.design의 X 모션 스터디(Bloom, Liquid Button)에 치우쳐 있고 어워드 수상 사이트에서는 확인되지 않았다. B 자신의 T4도 확산도 "중"을 "약~중"으로 낮춘다.
- A 사례 7·13은 목록 확인뿐이다. 예를 들어 A는 metic.을 목록에서만 확인했지만, B는 실제 사이트에서 빌드 시퀀스와 렌즈를 확인했으므로 A 문서의 근거로 보강할 수 있다.
- C-T6(창업자 목소리로 신뢰 확보): YumLog·JKK는 노미니나 일반 사이트라 어워드 근거로는 약하다. 다만 원칙으로는 타당하다.
- C-T8 FAQ: 근거가 노미니 두 곳뿐이다. 트렌드라기보다 전환 관점의 상식에 가깝다(채택은 무방).
- B 자체 반성: Cartier·Overworld·Huy Phan의 모션은 태그 기반 [추정]이다. T6(탐험형 공간)은 어워드 상위권 근거로는 강하지만 SaaS 적용 근거로는 약하다.

## 3. 충돌하는 제안과 B의 판단
| 쟁점 | A / C 입장 | B 판단 |
|---|---|---|
| 흑백 + 포인트 1색 vs "활기" | A: 무채색 + 1색 | 동의한다. 활기는 색 수가 아니라 모션(카운트업·토글 전환·CTA 모핑)에서 낸다. C의 "콘텐츠 모션으로 활기"와도 같다. |
| 역할 구분 수단 | A: 같은 색의 명도 차 / B: 토글로 팔레트 전환 | A안을 채택한다. 토글은 색조 전환 대신 명도·배경 톤 전환을 clip-path wipe(400ms 이하)로 처리한다. |
| 그래픽 모티프 | A: 지원자 = 콜라주, 헤드헌터 = 도트 매칭 | 도트 매칭(A-T4)만 채택하고 섹션 하나로 제한한다. Skiper39 배경과 질감 카드, 도트까지 동시에 쓰면 A 스스로 경고한 "트렌드 조금씩 섞기"가 된다. 질감은 카드 내부의 미세 그레인 정도로만 둔다. |
| 마퀴 | C: 포트폴리오 마퀴 / B: 마퀴 남용 경고 | 1개만 허용한다. 실제 작업물을 쓰고, 호버·포커스 시 정지하며, reduced-motion이면 정적 그리드로 바꾼다. |
| 히어로 데모의 무게 | C: 미니 데모 / B: 인스펙터 목업 + 3D 비권장 | 하나로 합친다. DOM 기반 카드와 인스펙터 패널을 anime.js 타임라인으로 루프하고(더미 데이터), WebGL은 쓰지 않는다. |
| 섹션 수 | C: 8개 섹션 | 모션 밀도를 고려해 4번(Fit Report 해부)을 3번(워크스루)의 마지막 단계에 합치는 것을 권한다. 스크롤 시퀀스가 두 번 반복되면 지루하다. |

## 4. 최종 트렌드 Top 6 (세 문서 통합, 추천 순)
1. **제품이 곧 히어로**: 역할 토글에 따라 바뀌는 DOM 데모(JD → 후보 카드 → 핏 점수, 인스펙터 콜아웃). 근거는 C-T1, B-T6, A-T6. anime.js 난이도 중.
2. **스크롤 시나리오 워크스루 + HIL 승인 하이라이트**: 업로드 → 분석 → 승인 → 제안을 스크러빙으로 보여 주고 점수를 카운트업한다. 근거는 C-T2·T3, B-T1·T7. 난이도 중.
3. **무채색 + 포인트 1색, 활기는 모션으로**: 근거는 A-T1, C 결론. 난이도 하.
4. **키네틱 한글 디스플레이 타이포**: 직무명 회전과 호버 스크램블(고정폭, aria-label). 근거는 A-T2, B-T3. 난이도 하.
5. **실물 포트폴리오 스트립 + 구체적 숫자**: 마퀴는 1개만 쓰고 수치는 예시라고 표기한다. 근거는 A-T6, C-T4·섹션2. 난이도 하.
6. **절제된 마이크로인터랙션 세트**: CTA 모핑, 카드 포인터 팬·틸트, 토글 clip-path wipe. 근거는 B-T4·T5·T8, C-T7(단일 동사형 CTA). 난이도 하~중.

공통 전제는 세 가지다. prefers-reduced-motion을 지원하고, 모든 인터랙션에 키보드 대체 수단을 두며, WebGL·프리로더·스크롤 하이재킹은 쓰지 않는다.
