# C. 제품 랜딩 구조·콘텐츠 전략 리서치 (2026-10-25)

조사자: 기획자 C. 방법은 WebFetch로 각 어워드 목록을 가져온 뒤 SaaS·제품 성격의 수상작 실제 사이트를 가져와 구조를 확인하는 방식이었다.
표기 규칙: **[확인]**은 실제 사이트 본문을 가져와 구조를 확인한 것이고, **[목록]**은 어워드 목록에서 제목과 URL만 확인한 것이다(구조는 보지 않았다).
한계: 사이트를 텍스트로 변환해 읽었기 때문에 모션과 시각 요소는 직접 보지 못했다. 2026년 Awwwards SOTD는 에이전시·포트폴리오·럭셔리 사이트가 대부분이고 순수 SaaS는 드물다.

## 2. 트렌드

1. **히어로 = 만져보는 제품 (인터랙티브 데모 히어로)** — 근거: Heron(드래그로 위반 사항 공개), YumLog(예시 프롬프트와 실제 화면), Butter(다이얼·슬라이더 GIF). 확산도: 강. 적용: 히어로 우측에 "JD 한 줄 → 후보 카드에 핏 점수가 뜨는" 미니 데모를 둔다(정적 더미 데이터로 루프 재생). 주의: 실제 API를 호출하지 말고 더미 데이터로 재생한다. 과하면 무거워진다.
2. **AI + 사람 승인 흐름을 카피에 명시** — 근거: Heron("proposes fixes it applies after approval", Observe→Advise→Act→Learn), Sidebar Deslop(짚기→정리). 확산도: 중(AI 제품에서는 강). 적용: Talentfolio의 핵심 차별점인 "에이전트가 찾고, 헤드헌터가 승인한다"를 히어로 서브카피나 단계 섹션 제목으로 쓴다. 주의: "AI가 다 해준다"는 과장을 피하고 사람의 결정권을 강조한다.
3. **피처 그리드 대신 시나리오 워크스루** — 근거: YumLog(대화 데모를 연속 배치), Butter(블록 → 커스터마이즈 → 저장 흐름), Heron(스크롤 콜아웃). 확산도: 강. 적용: "3단계 사용법" 카드를 실제 화면 조각이 스크롤에 맞춰 바뀌는 스토리로 교체한다.
4. **구체적이고 실재감 있는 숫자·데이터 조각** — 근거: Arg(2,000 TPS, 배포 1,000회), Heron(94%, 16.8 hrs), Dwell(비교 차트와 실제 가격 예시), CRL(포맷별 개수). 확산도: 강. 적용: "핏 점수 87 · 기술 스택 92 · 경험 81" 같은 리포트 조각과 등록 포트폴리오 수를 쓴다. 주의: 서비스 초기라면 허위 사용자 수를 쓰지 말고 예시라고 표기한다.
5. **양면 시장을 선택지로 분기** — 근거: Dwell(living/trades 선택과 For trades nav), Half the Sky(동사형 CTA 두 개). 확산도: 중. 적용: 현재 "두 역할 카드"를 히어로 안의 토글/세그먼트("올리러 왔어요 / 찾으러 왔어요")로 끌어올리고, 선택에 따라 아래 데모와 카피가 바뀌게 한다.
6. **신뢰는 로고보다 실명 사례·창업자 목소리로** — 근거: YumLog(founder note), JKK(창업자 메시지와 실명 Works), Arg(실제 프로젝트명). Heron은 이름 없는 로고라 설득력이 약하다(반면교사). 확산도: 중. 적용: 실제 포트폴리오 샘플 카드 몇 개와 만든 사람의 한 문단을 넣는다.
7. **단일 동사형 CTA 반복** — 근거: Dwell("Build your home" 반복), YumLog(App Store CTA 3회), Grok Upsell(단일 CTA), CRL("Enter Library"). 확산도: 강. 적용: 역할별 CTA를 각각 하나로 고정한다("포트폴리오 올리기" / "인재 찾기"). nav·히어로·마지막에 같은 문구를 쓴다.
8. **FAQ를 전환 직전 장치로** — 근거: YumLog, Dwell. 확산도: 중. 적용: "AI가 내 포트폴리오를 어떻게 쓰나요?", "헤드헌터 연락은 누가 승인하나요?"처럼 개인정보와 HIL 불안을 해소한다.

## 3. 피해야 할 패턴 (AI 생성 느낌 포함)

- 아이콘 + 제목 + 두 줄 설명으로 된 **뻔한 3열 피처 카드**(현재 "3단계 사용법"과 역할 카드가 이 형태에 가깝다). Heron의 4-카드 문제 섹션도 이 계열이다.
- 이름 없는 로고 스트립, 출처 없는 "10,000+ 사용자" 숫자.
- 같은 카피를 반복하는 섹션(Butter에서 관찰됨). 섹션마다 새 정보를 줘야 한다.
- "혁신적인 AI로 채용을 재정의" 같은 추상 슬로건, 보라-파랑 그라데이션 + 글로우 오브 + 반짝이 이모지 조합.
- 제품 화면 없이 일러스트나 스톡 인물만 쓰는 구성. 의미 없는 "Learn more" CTA가 여러 개 나열되는 것.
- 두 역할을 동등한 카드 두 장으로만 나열하고 이후 흐름이 갈리지 않는 구조.

## 4. Talentfolio 메인 섹션 구성 제안

| # | 제안 섹션 | 현재 대비 변경 |
|---|---|---|
| 1 | **히어로 + 역할 토글**: 헤드라인 "올리는 사람과 찾는 사람을 나눈다"는 유지한다. 그 아래에 [올리러 왔어요 / 찾으러 왔어요] 세그먼트를 두고, 우측에 선택에 따라 바뀌는 미니 데모(지원자: 포트폴리오 카드 생성 / 헤드헌터: JD → 핏 점수가 뜨는 후보 리스트)를 둔다. | 두 역할 카드를 히어로로 흡수하고 정적 히어로를 데모형으로 바꾼다. |
| 2 | **실재감 스트립**: 실제 포트폴리오 샘플 카드가 가로로 흐르는 마퀴(직군 태그와 스택 칩 포함). | 로고 월 대신 플랫폼의 실제 자원을 보여준다. |

| 4 | **Fit Report 해부**: 실제 리포트 카드 하나를 크게 보여주고 기술 스택·경험·컬처 점수와 근거 문장에 콜아웃을 단다(Heron식 주석). | 신규 섹션이다. 제품의 핵심 가치를 증명한다. |

| 6 | **신뢰 장치**: "에이전트는 제안하고, 사람이 결정합니다" 원칙과 개인정보 처리 방식, 만든 사람의 메모. | 신규 섹션이다. |
| 7 | **FAQ**(4~6개) | 신규 섹션이다. |
| 8 | **마지막 CTA**: 히어로와 같은 역할별 동사형 CTA 두 개. | 기존 역할 선택 CTA는 유지하되 문구를 히어로와 통일한다. |

배경(밝은 회색과 은은한 애니메이션)은 유지한다. 활기는 배경이 아니라 데모·마퀴·점수 카운트업 같은 **콘텐츠 모션**에서 끌어낸다.
