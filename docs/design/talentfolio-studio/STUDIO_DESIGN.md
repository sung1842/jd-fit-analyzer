# /studio 구직자 스튜디오 — 설계 v0.1 (2026-10-27)

> 루프 기여 한 줄: 구직자가 남기는 데이터를 **구조화된 "조각"**으로 받아, 스카우트 루프의 **후보 탐색·핏 분석 입력 품질**을 높인다.
> 대상: 개발자·디자이너뿐 아니라 사무직·요리사·체육교사 등 **전 직군**.

## 1. 컨셉 — "그려 보세요"

어릴 적 선생님이 "네 생각을 그림으로 그려 보세요"라고 하면, 잘 그리든 못 그리든 누구나 자기 이야기를 냈다.
스튜디오는 그 경험을 옮긴다. **사용자는 말하듯 적고, AI는 크레파스 역할**만 한다.

- 화면이 던지는 건 양식이 아니라 **질문**이다. 예: "가장 뿌듯했던 하루를 들려주세요", "동료가 당신을 부를 때 뭐라고 하나요?"
- AI는 답을 받아 **표현 카드 초안 2~3안**(타임라인·숫자·한 장 포스터 등)을 만든다. 고르고 고치는 건 사람.
- AI가 만든 건 늘 "초안" 배지가 붙고, 사용자가 확정해야 공개된다. 사실(경력·숫자)은 지어내지 않는다.

## 2. 정보 구조 (IA)

```
/studio
├─ 개요        완성도, 다음에 할 일 1개, 기업 열람/연락 수
├─ 프로필      기본정보 · 경력 · 학력 · 자격/수상 · 희망 조건(직무·지역·연봉 공개 여부)
├─ 나를 보여주기  "조각" 보드 (아래 3장)  ← 기존 "작업물" 탭 확장
├─ 자기소개서   여러 버전 관리, 공고별로 고르는 기본본 1개
└─ 공고        기존 관심·지원·보류 3칸 유지
```

- 레이아웃: 좌측 고정 섹션 내비(240px) + 본문 1열. 모바일은 상단 가로 탭.
- 오른쪽 위에 **"기업에게 이렇게 보여요" 미리보기** 토글. 지금 편집한 게 스카우트 화면에서 어떻게 보이는지 바로 확인.

## 3. 조각(Piece) — 표현 단위

모든 직군이 같은 틀 안에서 고를 수 있게, 형식은 몇 개로 고정하고 내용은 자유롭게.

| 조각 | 무엇 | 예 (직군 무관) |
|---|---|---|
| 작업물 | 파일·이미지·링크 | 디자인 시안, 레포, 요리 플레이팅 사진, 수업 지도안 PDF |
| 이야기 | 상황→행동→결과 3칸 | "월말 정산 오류 40건을 하루에 정리" |
| 나의 하루 | 시간대별 타임라인 | 체육교사의 수업일, 셰프의 오픈 준비 |
| 숫자 | 숫자 1~3개 + 한 줄 | "고객 재방문율 32%→51%" |
| 일하는 방식 | 원칙·습관 3가지 | "기록부터 한다 / 혼자 막히면 30분 안에 묻는다" |
| 한 장 | 사진 1장 + 캡션 | 현장 사진, 손글씨 메모 |
| 추천사 | 동료·상사의 한마디 | 링크 요청 → 받은 글만 표시 |

- 보드에서 순서를 드래그로 바꾸고, 대표 조각 3개를 고르면 그게 기업 카드에 뜬다.
- 직군을 고르면 **추천 질문 세트**만 바뀌고 틀은 같다 (요리사 → "시그니처 메뉴를 만든 과정은?").

## 4. AI 흐름 "말로 그리기"

1. 질문 선택 → 자유롭게 적기 (나중에 음성 입력)
2. 서버 라우트에서 Gemini Flash 호출, `responseJsonSchema`로 조각 형식 강제 (헌법 1조)
3. 초안 2~3안을 나란히 보여 줌 → 골라서 편집 → 저장
4. 입력은 사용자가 적은 텍스트만, 길이 상한 두고 정리해서 넣는다 (헌법 3조). 1회 요청 = 1회 호출.
5. 생성 실패해도 같은 내용을 직접 입력 폼으로 이어서 쓸 수 있게 한다.

## 5. 디자인 원칙 (메인과 다르게, 조용하게)

- **정리**: 8px 그리드, 카드 테두리 1px + 그림자 없음, 섹션 제목·숫자·본문 3단계 위계만.
- **글꼴**: Pretendard 하나 (+ 로고만 Lora). 강조는 굵기와 파란색(#1F4FD6)으로만.
- **모션**: anime.js, 150~250ms. 카드 등록 시 위로 4px 떠오르며 들어오기, 탭 전환 시 밑줄 이동, 완성도 바 채우기. 그 이상은 없음.
- **AI 티 안 내기**: 반짝이(✨) 아이콘·보라 그라데이션·빛나는 테두리·"AI가 당신을 분석했어요" 문구 금지. 버튼 이름은 "초안 받아 보기"처럼 행동 중심으로.
- 빈 상태는 질문 하나로 시작 ("오늘 했던 일 중 하나만 적어 볼까요?").

## 6. 데이터 (talentfolio Supabase, 초안)

- `profiles` 확장: 직군(대분류), 희망 조건, 공개 범위
- `career_entries`, `education_entries`, `certifications`
- `pieces`: id, profile_id, type, title, body(jsonb, type별 스키마), media[], order, is_featured, source(`manual`|`ai_draft`), status(`draft`|`published`)
- `cover_letters`: 버전별 본문, is_default
- 스카우트 쪽 `search_candidates`/핏 분석은 published 조각의 정리된 텍스트만 읽는다.

## 7. 단계

1. **S1** 구조 개편: 섹션 내비 + 프로필/경력/자소서 폼 + 조각 보드(직접 입력 7종). 저장은 지금처럼 로컬 → 이후 Supabase.
2. **S2** "말로 그리기" AI 초안 + 직군별 질문 세트
3. **S3** 기업 미리보기 + 대표 조각을 스카우트 카드·핏 분석에 연결
4. **S4** 추천사 요청, 음성 입력

## 8. 확인할 것

- 직군 분류 기준 (사람인/잡코리아 대분류를 따를지)
- 개인정보(연락처·생년 등) 중 기업에 기본 비공개로 둘 항목
- S1 저장을 바로 Supabase 테이블로 갈지, 로컬 데모로 먼저 화면을 볼지
