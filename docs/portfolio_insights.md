# 포트폴리오 인사이트 노트

> 이 프로젝트를 하면서 나온 **좋은 아이디어·판단·근거**를 모아 두는 문서. 나중에 포트폴리오·지원서에 녹인다.
> 사용자가 "좋은 것 정리해줘" 하면 여기에 항목을 추가한다 (최신이 아래). 항목마다: 핵심 한 줄 → 근거 → 이 프로젝트에서의 구현/연결.

---

## 1. 핵심 차별점: AI는 구직자의 "대필자"가 아니라 "증거를 캐내는 인터뷰어" (2026-10-27)

**한 줄**: 빅테크·채용 플랫폼은 기업 쪽(인재상 정형화·매칭)에 AI를 쓴다. 병목은 구직자 쪽 신호 품질이다.
구직자 쪽에도 AI를 쓰되, 글을 대신 써 주는 게 아니라 **꾸미기 어려운 증거를 끌어내 구조화**하게 한다.

### 문제 진단 (근거)
- 채용은 정보 비대칭 시장 — 기업은 역량을 직접 못 보고 신호에 의존한다 ([LinkedIn Economic Graph 워킹페이퍼](https://economicgraph.linkedin.com/content/dam/me/economicgraph/en-us/PDF/skills-signals-unemp-wp.pdf): 프로필 스킬 10개 추가 → 구직 공백 중앙값 약 1개월 단축. 회사 소속 연구).
- 정보가 부족하면 유능한 사람도 안 뽑힌다 — Pallais, *AER* 2014: oDesk 신입에게 상세 공개 평가 제공 → 이후 고용 크게 개선 ([NBER w18917](https://www.nber.org/papers/w18917)).
- "스킬 중심 채용"은 말뿐 — 학위 요건 삭제 공고 약 400% 증가, 실제 비학위 채용은 약 3.5% 증가 (Harvard PMFoW·Burning Glass 2024, [요약](https://pw.hks.harvard.edu/post/skills-based-hiring-the-long-road-from-pronouncements-to-practice)). 기업이 스킬을 믿을 근거가 없다.

### 함정: AI로 "잘 쓰게" 하면 신호가 무너진다 (근거)
| 연구 | AI 역할 | 결과 |
|---|---|---|
| Wiles·Munyikwa·Horton, *Management Science* 2025 ([NBER w30886](https://www.nber.org/papers/w30886)) | 본인 글 **교정** | 고용 +8%, 임금 +10%, 기업 만족도 하락 없음 |
| Cui·Dias·Ye, "Signaling in the Age of AI" 2025 워킹페이퍼 ([arXiv](https://arxiv.org/html/2509.25054v2), [Wharton](https://knowledge.wharton.upenn.edu/opinion/ai-is-killing-the-cover-letter/)) | 지원서 **생성** | 일치도·회신율 ↑, 그러나 일치도-회신 상관 51% ↓, 기업은 과거 작업 이력으로 이동. 초안 편집 시간 ↔ 채용 성공 양의 상관 |
| Galdin·Silbert ([CNN/HospitalityNet](https://www.hospitalitynet.org/external/4130281.html)) | ChatGPT 이후 지원서 | 글은 좋아졌지만 덜 신뢰 → 채용률·초봉 하락 |

- 원리(신호 이론): 꾸미기 쉬운 신호는 가치가 없고, 속이기 어렵거나 비용이 드는 신호만 믿을 수 있다 ([LinkedIn 성격 신호 연구](https://escholarship.org/uc/item/2bt1q6vw)).
- 개발자 채용자는 이력서보다 공개 작업 흔적(GitHub)을 더 믿는다 — "꾸미기 어려워서" ([Marlow & Dabbish, CSCW 2013](https://www.cs.cmu.edu/~xia/resources/Documents/Marlow-cscw13.pdf)).
- 프로필의 자기표현 논거 품질이 채용 추천 의도를 예측한다 ([LinkedIn 자기표현 연구, 2015](https://scholar.lib.ntnu.edu.tw/en/publications/self-presentation-and-hiring-recommendations-in-online-communitie-2/)).

### 설계 원칙
| | 피할 것 | 할 것 |
|---|---|---|
| AI 역할 | 자기소개 대필 | 프로젝트별 질문으로 사실·근거 추출 (문제, 내가 한 것, 결과 수치, 커밋·PR·산출물 링크) |
| 산출물 | 매끈한 문단 | **증거 카드** = 주장 1개 + 근거 + 출처 |
| 신뢰 표시 | 없음 | `근거 확인됨 / 근거 첨부 / 본인 주장`, `본인 작성 / AI 교정` |
| 공고별 지원 | 회사마다 새로 생성 | 같은 증거 카드를 **고르고 순서만** 바꿈 (없는 주장 생성 금지) |

### 사람들이 여기 와서 써야 하는 이유
| 지금 방식 | 문제 | 이 서비스 |
|---|---|---|
| 구직 때만 몰아서 작성 | 기억·수치 소실 | **커리어 로그**: 일이 끝날 때 AI 2분 인터뷰로 적립 |
| 회사마다 자소서 새로 | 비용 큼, 내용 불일치 | 카드 한 번 작성, 공고별로 선택만 |
| 노션·PDF·GitHub 분산 | 기업이 훑고 지나감 | 근거를 카드에 연결, 요약+근거 함께 노출 |
| 내 적합도를 모름 | 피드백 없음 | 공고별 핏 분석 + 부족한 증거 안내 |

→ "써야 해서 쓰는 곳"이 아니라 "기록해 두면 지원·피드백이 따라오는 곳".

### 이 프로젝트와의 연결
- jd-fit 분석(기술 스택·경험·트러블슈팅) — 증거 카드를 입력으로, 근거를 인용하는 리포트 (환각 감소, 헌법 3조와 같은 방향).
- 포트폴리오와 대화하기(RAG, Phase 5) — 기업 질문에 증거 카드를 인용해 답.
- 헤드헌터 HIL 승인 — 근거 확인 여부를 보고 빠르게 판단.

### 위험·한계
- 비공개 사내 성과는 검증 불가 → 숨기지 말고 "본인 주장"으로 표시.
- 증거 카드도 결국 조작 경쟁 → 출처 링크·시점 기록이 방어선.
- 근거 연구 대부분이 미국·프리랜서 플랫폼, Cui 연구는 동료 심사 전 → 한국 정규직 채용에 그대로 일반화하지 말 것.

### 타깃 판단 (같은 날 논의)
- 수익(헤드헌팅 수수료)은 경력직에서 성립. 다만 고스펙층은 리멤버·링크드인이 선점 → **"스펙 대신 증거" 1~7년차 IT 실무자(개발·디자인)** 가 증거 기반 매칭의 강점이 가장 잘 드러나는 층. 신입은 유입·미래 후보 풀.

## 2. 제품 형태: 일기 + 포트폴리오 + AI — "대화로 쌓고, 내가 골라 보여 준다" (2026-10-27)

**한 줄**: 활동 하나하나를 AI와 대화하듯 기록(일기)하고, 그중 자랑하고 싶은 것만 골라 가공·공개(포트폴리오)하면, 기업은 공개된 것만 AI로 정형화해 매칭한다.

### 생각의 흐름 (어떻게 여기까지 왔나)
1. **자소서·이력서(글)만으로는 AI 시대에 사람을 평가하기 어렵다.** AI가 쓴 글은 완벽에 가까워 채용자의 불신만 키운다 (1번 항목의 연구).
2. **정형 데이터(경력·스펙)는 오래된 방식이라 차별점이 없고, 회사 적합도를 알기 어렵다.** → 구직자는 **비정형**을 올리고, 기업이 AI로 정형화에 가깝게 필터링하는 구조여야 한다.
3. **작품이 없는 직무도 표현할 수단이 필요하다.** "나를 그림으로 그려 보세요"처럼 **큰 틀은 주고 표현은 자유롭게** → 6칸 캔버스.
   - 근거: 인사선발 메타분석에서 **구조화 면접(같은 질문·같은 기준)** 이 예측 타당도 1위 (Sackett 외, *J. Applied Psychology* 2022, [요약](https://www.humrro.org/?p=5963)). 큰 틀 + 자율 표현 = 구조화 면접의 비동기·자율 버전.
4. **활동 단위(건 바이 건)로 관리하는 일기** — 단체·개인 프로젝트, 활동, 실무, 자잘한 활동 전부. 이력을 넘어 "살아온 삶"을 관리하는 곳이 되어 자연스럽게 다시 찾게 된다.
5. **기록 피로는 대화형 AI로 푼다.** 심심풀이로 아무 말이나 하면 AI가 정리해 두고, 의욕이 생겼을 때 들어오면 초안이 이미 있다 → 시작 부담이 낮다. AI는 듣기만 하지 않고 **티키타카로 질문**하며, 6칸 캔버스를 상황에 맞게 대화에 녹여 기록을 깊게 만든다.
6. **SNS로 단련된 "기록하고 자랑하는 능력"을 활용한다.** 기록은 기본 비공개, 자랑하고 싶은 것만 외부에 노출.
7. **최종 결정 — 비공개 데이터는 전적으로 사용자에게 맡긴다.** 모든 대화는 정리해 저장하되, 무엇을 가공하고 노출할지는 사용자가 고른다. **기업 매칭에는 사용자가 고른(공개한) 것만 쓴다.**

### 6칸 캔버스 (대화 속 질문의 뼈대)
| 칸 | 질문 | 드러나는 것 |
|---|---|---|
| ① 내가 푼 문제 | 가장 자랑스러운 문제 해결 | 문제 해결력·주도성 |
| ② 실패와 회복 | 잘 안 된 일과 그 뒤에 한 일 | 학습력·정직성 |
| ③ 일하는 방식 | 나와 일하는 법 ("나 사용설명서") | 협업·컬처핏 |
| ④ 남들이 나를 찾는 이유 | 동료가 주로 부탁하는 것 | 실제 강점 |
| ⑤ 증거 | 뒷받침하는 것 | 신뢰도 |
| ⑥ 다음 | 다음에 하고 싶은 일 | 동기·방향 |

- 작품 없는 직무의 "작품" = **과정과 판단**: 영업(딜 회고·실적 추이), 마케팅(가설→결과), 기획(의사결정 문서), 인사·운영(프로세스 전후), 회계(자동화·마감 단축), CS(까다로운 사례 재구성).

### 설계 원칙 (대화하며 확정)
- **대화 품질이 곧 서비스**: 느리거나 일관성 없으면 떠난다. 대화는 빠른 중간급 모델 + 스트리밍, 일관성은 전체 기록 대신 **"이 사람 요약 기억"** 으로. 무거운 구조화는 대화 종료 후 1회(큐).
- **유도 질문 금지**: "리더십을 발휘하셨네요?" 대신 사실을 묻는 열린 질문. 과장된 기록을 막는다.
- **초안은 사용자의 말로**: AI는 인용·정리만, 하지 않은 말은 넣지 않는다 (1번 항목: 생성은 신호를 죽이고 교정은 살린다).
- **공개 글에 기록 시점 배지** ("활동 당시 작성"): 구직 직전에 꾸민 자랑이 아니라는 증거 → 꾸미기 어려운 신호. 일반 SNS 자랑과의 결정적 차이.
- **소셜 기능은 최소로**: 피드·좋아요는 과시 경쟁과 소음을 키운다. 처음엔 단체 활동의 "같이 했어요" 동료 확인만 (제3자 증거 + 유입).
- 비유: **Strava**(매일 비공개 기록 → 자랑할 기록만 공유) + **GitHub**(작업 흔적이 곧 프로필). 이력서는 따로 쓰는 게 아니라 공개 기록에서 만들어지는 산출물.

### 비공개 데이터 논의 → 최종 결정
- 처음 안: 비공개 기록도 AI 분석(비정형 인적성)에 쓰고, 기업에는 추천만 주고 판단은 면접에. 가입 시 동의.
- 짚은 문제: ① 일상 기록의 민감정보(건강·가족·종교)가 점수에 섞이면 내용을 안 보여 줘도 결과가 차별이 된다 (민감정보는 별도 동의 영역). ② 자동화된 결정에 대한 설명·거부권 (개인정보보호법 제37조의2). ③ "일기가 평가된다"는 걸 알면 일기를 꾸미기 시작해 솔직함이 사라진다.
- **결정: 사용자에게 전적으로 맡긴다.** 비공개 = 본인용 AI(정리·초안·코칭)에만. 기업 매칭 = 사용자가 직접 가공·공개한 것만. → ①②③이 구조적으로 해소되고, 일기의 솔직함이 유지된다.

### 한 문장 정의
> **기록은 비공개 일기(AI와의 대화), 공개는 포트폴리오(내가 골라 가공), 연결은 AI(공개분만으로 기업 매칭).**
