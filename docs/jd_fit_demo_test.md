# JD-Fit 분석 테스트 영상 촬영 가이드

> 작성 2026-11-06. 2026-11-06 리허설(임시 기업 계정, 리허설 뒤 탈퇴 처리) 결과를 기준으로 적었다.
> 공고는 크롤링 수집 공고(테스트 전용)를 입력 양식에 맞게 다듬은 것이다. 영상을 공개한다면 회사명은 빼고 쓴다.
> 보여 줄 흐름: 공고 입력 → 코드 사전 필터 → AI 핏 분석 → 헤드헌터 승인 → 제안

## 0. 촬영 전 준비

| 확인 | 방법 | 기대 결과 |
|---|---|---|
| 서버 | `docker compose ps` | orchestrator-api·worker, mcp-server, redis 모두 healthy |
| 화면 | http://localhost:3000 | 메인이 열린다 |
| Gemini 한도 | `docker logs --since 10m jd-fit-analyzer-mcp-server-1 2>&1 \| grep -c 429` | 0 |
| 종합 의견 모드 | 아래 "종합 의견(CEO)" 참고 | 실제 Claude 를 쓸지 결정 |
| 계정 | 기업 계정 `test1234@talentfolio.com` 로그인 | /desk 로 이동 |
| 브라우저 | 창 크기 1920×1080, 확대 100%, 알림 끄기 | |

### 종합 의견(CEO)
지금 컨테이너는 `CEO_MOCK=true` 다. 점수는 Gemini 분석 결과의 가중 평균이고, 종합 의견은 Claude 호출 없이 아래 고정 문구로 나온다.

> 종합 의견 없이 기술·경험·컬처핏 점수를 가중 평균한 참고 점수입니다. 근거와 면접 확인 질문을 보고 판단하세요.

Claude 의 실제 종합 의견을 찍으려면 `.env.local` 의 `CEO_MOCK` 을 끄고 컨테이너를 다시 띄운 뒤 리허설한다. (Anthropic 비용 발생)

### 같은 공고는 한 번만 실제로 분석된다
같은 (공고 내용, 후보) 는 캐시되어 다시 찍으면 진행 과정 없이 바로 끝난다. **재촬영할 때는 조직문화 문장을 한 글자라도 바꾼다.**

## 1. 입력 데이터

### 공고 A — 메인 시연: Java 백엔드
원문: 「Java Web Backend 개발자 채용」 (경기 용인시 기흥구, 신입·경력 5년 이하)

- **모집 직군**: 개발자
- **모집 인원**: 1

**자격요건 · 필수 기술**
```
Java
Spring Boot
JPA
```

**우대사항**
```
PostgreSQL 쿼리 최적화·인덱스 튜닝 경험
Spring Cloud 기반 MSA 설계·개발 경험
Docker 컨테이너 배포 경험
CI/CD 환경 구축·운영 경험
```

**주요업무**
```
반도체·디스플레이 불량분석 솔루션의 Backend/API 서버 개발 (Java, Spring Boot, JPA)
대용량 데이터 수집 및 처리 성능 최적화
컨테이너 기반 배포 및 CI/CD 파이프라인 운영·개선
프론트엔드와의 API 인터페이스 협의 및 데이터 연동 구조 설계
```

**조직문화**
```
Git 기반 코드 리뷰 협업, 선택적 시차 출퇴근(8~10시 출근), 학습과 성장 지향
```

> 필수 기술에 `PostgreSQL·Linux·Git` 까지 넣지 말 것. 리허설에서 상위 후보가 모두 "필수 미충족"이 되어 순위 점수가 50 으로 같아지고 정밀 분석 대상에서 빠졌다.

### 공고 B — 직군 필터 시연: UI/UX 디자이너
원문: 「UI/UX 디자이너 신입/경력」

- **모집 직군**: 디자이너
- **모집 인원**: 1

**자격요건 · 필수 기술**
```
Figma
UI Design
UX Research
```

**우대사항**
```
디자인 시스템 구축 경험
프로토타이핑 및 인터랙션 설계 경험
Admin / CMS 디자인 경험
```

**주요업무**
```
웹/모바일 서비스 UI/UX 디자인
서비스 UX 구조 및 사용자 흐름 설계
디자인 시스템 및 가이드 구축, 프로토타입 제작
```

**조직문화**
```
개발·기획팀과 긴밀한 협업, 자유로운 연차 사용, 강요 없는 회식
```

### 제안 메시지 (공고 A)
```
안녕하세요. 반도체·디스플레이 불량분석 솔루션의 Java/Spring Boot 백엔드 포지션을 제안드리고 싶어 연락드립니다.
공개하신 작업 근거를 보고, 대용량 데이터 처리와 API 설계 경험이 저희 팀에 잘 맞는다고 판단했습니다.
경기 용인(기흥) 근무, 선택적 시차 출퇴근이 가능합니다. 관심 있으시면 편하신 시간에 짧게 이야기 나눠 보고 싶습니다.
```

## 2. 촬영 순서

| 장면 | 할 일 | 화면에서 보여 줄 것 | 예상 시간 |
|---|---|---|---|
| 1. 시작 | /desk 에서 스카우트 건 현황·승인 대기 숫자를 보여 준다 | 시작 전 숫자 (마지막에 비교) | 10초 |
| 2. 공고 입력 | **인재풀** (/desk/candidates) → **JD 매칭** → 공고 A 를 칸별로 붙여넣기 | 구조화된 입력 칸 | 30초 (미리 복사해 두기) |
| 3. 사전 필터 | **분석 시작** | "개발자 80명 중 키워드 매칭 20명 · 5명씩 분석" 문구. AI 호출 전에 코드로 후보를 줄인다는 점 | 2초 |
| 4. AI 분석 | 진행 표시를 그대로 둔다 | 후보 5명의 진행 단계가 큐·SSE 로 실시간 변함 | 1분 안팎 |
| 5. 결과 | 완료 후 후보 카드를 연다 | 총점, 기술·경험·컬처핏 점수, 근거 | 30초 |
| 6. 약한 후보 대비 | **다음 5명 더 분석** 을 눌러 뒤쪽 후보를 본다 (선택) | 기술이 맞지 않는 후보의 낮은 점수 | 1분 |
| 7. 사람 승인 | /desk → 해당 건 카드 → /review → 근거 확인 → **A** 승인 1명, **R** 거절 1명(사유 선택) | AI 가 결정하지 않고 사람이 판단 | 40초 |
| 8. 제안 | 승인 후보에 제안 메시지 붙여넣기 → **제안 초안 만들기** → /desk 제안 패널 → **발송 승인** | 후보에게 갈 본문 확인 뒤 발송 승인 | 40초 |
| 9. 직군 필터 | 다시 JD 매칭 → 공고 B | "디자이너 19명 중 키워드 매칭 17명". 개발자가 대상에서 빠짐 | 20초 (결과까지 찍으면 1분 더) |
| 10. 마무리 | /desk 로 돌아온다 | 승인 대기·결정 기록이 바뀐 숫자 | 10초 |

주의:
- 후보를 골라 **Slack 승인 요청**을 누르면 실제 Slack 채널로 메시지가 나간다. 연동 전에는 영상에서 누르지 말 것.
- **발송 승인**은 현재 기록만 남고 후보에게 실제로 메일·알림이 가지 않는다.

## 4. 문제가 생기면

| 증상 | 조치 |
|---|---|
| 진행 과정 없이 바로 끝남 | 캐시. 조직문화 문장을 바꿔 다시 실행 |
| "일시 오류로 재시도 중"이 반복 | Gemini 한도 확인 후 잠시 뒤 재시도 |
| 후보 점수가 모두 비슷하게 낮음 | 필수 기술이 너무 많음. 공고 A 입력값 그대로 사용 |
| 빈 목록 | `docker compose ps`, `docker logs --since 5m jd-fit-analyzer-orchestrator-api-1` |
| 로그인 후 /studio 로 감 | 구직자 계정. 로그아웃 후 기업 계정으로 |
